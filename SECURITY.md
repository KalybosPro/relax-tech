# Security Policy

Thank you for helping keep the **Relax** suite and its users safe.

## Reporting a vulnerability

Please report security issues **privately** so we can fix them before public
disclosure. Do **not** open a public issue for a vulnerability.

Preferred channels, in order:

1. **GitHub private advisory** — [open a draft security advisory](https://github.com/KalybosPro/relax-tech/security/advisories/new)
   (Security → Advisories → *Report a vulnerability*). This is the fastest and
   most private route.
2. If you cannot use advisories, email the maintainer and clearly mark the
   subject as `SECURITY`.

## What to include

- The affected package and version (e.g. `relax_cli 1.1.0`).
- A description of the issue and its impact.
- Steps to reproduce, and a minimal proof of concept if possible.
- Any relevant environment details (OS, Dart/Flutter version).

## Our commitment

- We will acknowledge your report as soon as possible.
- We will keep you informed as we investigate and prepare a fix.
- We will credit you in the release notes unless you prefer to remain anonymous.

## Supported versions

Security fixes are applied to the latest published release of each affected
package. If you are unsure whether your version is supported, mention it in your
report and we will advise.

## Disclosure

Please give us a reasonable window to release a fix before any public
disclosure. We are happy to coordinate a disclosure timeline with you.
